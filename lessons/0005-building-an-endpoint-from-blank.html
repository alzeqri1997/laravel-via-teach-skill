1Cold recall

From Lessons 2–4, no scrolling: name the files an API endpoint passes through, and say what each one is for. Then: why is $student->mosque inside a loop dangerous?

Chain: route (which controller, which middleware) → controller (handles the request) → model (what the thing is) → resource (which fields become JSON). Ethaaf adds service and repository between controller and resource.

N+1: property access on a relationship runs a query. In a loop over 500 rows that is 500 queries. Fix: eager load with with(), or withCount() when you only need the number.

Both are common interview questions. The N+1 one is near-guaranteed.

2The sequence

"Build an endpoint that lets a teacher record a student's progress." That is a take-home test. Here is the order — and the order matters, because each step depends on the one before:

php artisan make:migration

The table. Nothing can store data until the columns exist.

php artisan make:model Progress

The model. Fillable fields, casts, relationships.

php artisan make:request StoreProgressRequest

The gate. Validation rules — the real one, not the frontend's.

php artisan make:controller ProgressController --api

The handler. Thin: validate, act, return.

php artisan make:resource ProgressResource

The contract. Which fields reach the client.

Route::apiResource(...)

The wiring. Last, because it points at something that now exists.

Say this in an interview

Being able to recite this sequence — and explain why it runs in that order — is itself a strong signal. It says you have built something, not just read about it. Most candidates can name the pieces; fewer can order them and justify it.

3Writing it

① Migration

database/migrations/2026_10_18_000000_create_progress_table.php

public function up(): void
{
    Schema::create('progress', function (Blueprint $table) {
        $table->id();
        $table->foreignId('student_id')->constrained()->cascadeOnDelete();
        $table->unsignedSmallInteger('pages');
        $table->date('recorded_on');
        $table->timestamps();
    });
}

Three things an interviewer listens for here. foreignId()->constrained() creates the column and the foreign key, inferring the table from the name. cascadeOnDelete() states what happens to progress when a student is deleted — a deliberate decision, not a default. And timestamps() adds created_at/updated_at, which Eloquent maintains automatically.

② Model

app/Models/Progress.php

class Progress extends Model
{
    protected $fillable = ['student_id', 'pages', 'recorded_on'];

    protected $casts = [
        'recorded_on' => 'date',
        'pages'       => 'integer',
    ];

    public function student()
    {
        return $this->belongsTo(Student::class);
    }
}
Interview question: what is $fillable actually for?

It prevents mass-assignment vulnerabilities. Progress::create($data) with raw request data would otherwise let a caller set any column — including id, or on a User model, is_admin. $fillable is an allow-list. Being able to say the phrase "mass assignment" and explain the attack is a meaningful signal; many candidates know the property but not the reason.

③ Form Request — the heart of it

app/Http/Requests/StoreProgressRequest.php

class StoreProgressRequest extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()->can('create', Progress::class);
    }

    public function rules(): array
    {
        return [
            'student_id'  => ['required', 'integer', 'exists:students,id'],
            'pages'       => ['required', 'integer', 'min:1', 'max:604'],
            'recorded_on' => ['required', 'date', 'before_or_equal:today'],
        ];
    }
}

Two methods, two separate jobs, and interviewers probe the distinction: authorize() answers "may this user do this at all?" and rules() answers "is this data acceptable?" A failed authorize() returns 403; failed rules return 422 (docs).

Use it by type-hinting — validation runs before your method body:

public function store(StoreProgressRequest $request)
{
    $progress = Progress::create($request->validated());

    return new ProgressResource($progress);
}
The 422 your SPA has been receiving for years 
{
  "message": "The pages field is required. (and 1 more error)",
  "errors": {
    "pages":       ["The pages field is required."],
    "recorded_on": ["The recorded on field must be a date before or equal to today."]
  }
}

You have written frontend code against this exact shape. Now you know what produces it: a Form Request, automatically, with no error-handling code in the controller at all.

④ Resource, and ⑤ the route

// app/Http/Resources/ProgressResource.php
public function toArray(Request $request): array
{
    return [
        'id'           => $this->id,
        'pages'        => $this->pages,
        'recorded_on'  => $this->recorded_on->toDateString(),
        'student_name' => $this->whenLoaded('student', fn () => $this->student->name),
    ];
}

// routes/api.php
Route::middleware('auth:sanctum')->group(function () {
    Route::apiResource('progress', ProgressController::class);
});

whenLoaded() is the Lesson 4 defence, built into the Resource layer: include the relation only if it was eager loaded, so the Resource can never silently trigger an N+1. Using it unprompted in a take-home is a genuine signal of competence.

4How Ethaaf does validation

Your worked example, now that you can read it properly — MeasurementFormRequest, where a form's grades must total exactly 100:

public function rules(): array
{
    $measurementForm = $this->route('measurement_form');
    $uniqueRule = Rule::unique(MeasurementForm::class, 'name')->ignore($measurementForm);

    $rules = [
        'name'             => ['required', 'string', 'max:255', $uniqueRule],
        'elements'         => ['required', 'array', 'min:1'],
        'elements.*.name'  => ['required', 'string'],
        'elements.*.grade' => ['required', 'numeric', 'min:0'],
    ];
    // …
}

public function withValidator($validator): void
{
    $validator->after(function ($validator) {
        $total = collect($this->input('elements', []))->sum('grade');
        if ($total != 100) {
            $validator->errors()->add('elements', __('messages.measurement_form_grades_must_equal_100'));
        }
    });
}

Four techniques worth stealing, each answering a real interview question:

TechniqueWhat it solves
elements.*.grade Validating every item in an array — * is a wildcard
Rule::unique(...)->ignore($x) "Unique, except itself" — without it, every update fails its own uniqueness check
withValidator() Cross-field rules no single-field rule can express (the sum must be 100)
Conditional rules in rules() Rules that depend on the record being edited

Ethaaf also has a custom Rule::tenantExists('sections') — an exists check that respects tenancy, so a caller cannot reference another tenant's section by guessing its id. That is a good thing to describe in an interview: it shows you have seen validation used as a security boundary, not just a form-checker.

5Retrieval practice

A JSON request fails validation in a Form Request. What status code comes back?

What is $fillable on a model protecting you from?

Say this one out loud, as if to an interviewer. "Walk me through how you'd add a POST endpoint to a Laravel API." Speak it before you type.

A strong answer covers: migration (table) → model (fillable, casts, relationships) → Form Request (authorize + rules) → controller (thin: validated data in, resource out) → Resource (JSON contract) → route (apiResource, behind auth middleware).

What lifts it from adequate to good: mentioning that validation failures return 422 automatically, that $fillable guards mass assignment, and that you would eager load relations the Resource touches to avoid N+1. Those three asides signal real experience.

Did you actually say it aloud? Speaking recruits different retrieval than typing, and it is the skill the interview actually measures.

6Version shift

12 ← 10 · Ethaaf

Everything in this lesson works unchanged in Laravel 10, so Ethaaf's code reads the same. The one structural difference you will notice: Laravel 10 registers middleware in app/Http/Kernel.php; 11 and 12 use bootstrap/app.php. Ethaaf has the Kernel file. That is the single most common "why is this file missing?" moment when moving between versions.

12 → 13 · additions

Laravel 13 adds #[Middleware] and #[Authorize] PHP attributes on controllers, and first-party JSON:API resources. Neither exists in 12. If a tutorial shows attributes above a controller class, it is 13-only — use ->middleware() on the route instead.

7Your task before Lesson 6

One — build it, for real. This is the first lesson where reading is not enough. Create a throwaway Laravel 12 app and build the progress endpoint end to end:

composer create-project laravel/laravel:^12.0 practice-api
cd practice-api
php artisan install:api        # adds routes/api.php + Sanctum
php artisan make:model Progress -mrR

-mrR generates the migration, a resource controller and an API resource in one command. Then wire it up, and POST to it until you have seen with your own eyes: a 201 on success, a 422 with a bad payload, and a 404 for a missing id.

Two — say it out loud. Record yourself answering "how would you add a POST endpoint?" in under two minutes. Listen back once. This feels awkward and is the highest-value thirty seconds in the whole lesson — the gap between knowing and *saying* is where interviews are lost.

Three — bring me one question you could not answer. Whatever stumped you while building is exactly what Lesson 6 should address.
