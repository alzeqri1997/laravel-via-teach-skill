2Tenancy — the rules

One database. No tenant{id} databases; DatabaseTenancyBootstrapper is commented out and database/migrations/tenant/ is empty. Tables are separated by a tenant_id column.

Enforced by App\Models\Concerns\BelongsToTenant, which installs App\Models\Scopes\TenantScope and auto-fills tenant_id on create.

SituationIs the scope protecting you?
API request on a tenant routeYes — tenancy initialized
Filament admin panelNo — central context
Plain queue jobNo — unless wrapped in $tenant->run()
Console command / schedulerNo — central context
Inside $tenant->run(...)Yes — scope has a tenant
Three rules, non-negotiable

1. Never call bare withoutGlobalScopes() on a tenant model — it strips TenantScope plus the actor scopes and silently returns all tenants. Remove scopes by class name.
2. Bulk insert() bypasses the creating hook — supply tenant_id by hand.
3. When a scope is deliberately dropped, something explicit must replace it (see forTenants(...)). A drop with no replacement is a leak.

Actor scopes that also ride along: MosqueAdminScope, AdminStudentsScope, ParentStudentScope, SectionReviewingScope.

5The reading order for a ticket

route:list

Find the real URL and its middleware. URLs are assembled from nested prefixes and cannot be found by searching for the path.

Route file

Which permission guards it (associationPermission:…), which controller.

Controller

Thin. Note the injected Service in the constructor.

Service

Business decisions — and often the tenancy commentary worth reading.

Repository

The actual query, filters, and the isolation boundary.

Resource

Which columns reach the client. Where a "missing field" bug almost always is.
