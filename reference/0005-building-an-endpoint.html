Cross-field rules go in withValidator():

public function withValidator($validator): void
{
    $validator->after(function ($validator) {
        if (collect($this->input('elements', []))->sum('grade') != 100) {
            $validator->errors()->add('elements', 'Grades must total 100.');
        }
    });
}

5Interview answers

"Walk me through adding a POST endpoint."

Migration → model (fillable, casts, relationships) → Form Request (authorize + rules) → thin controller (validated in, Resource out) → Resource → route behind auth middleware. Add: validation failures return 422 automatically; $fillable guards mass assignment; eager load whatever the Resource touches.

"What is the N+1 problem?"

Accessing a relationship as a property runs a query, so a loop over N rows runs N extra queries. Fix with with() to eager load, or withCount() for counts only. Add: Model::preventLazyLoading() turns accidental lazy loads into exceptions in development.

"Why validate on the server when the frontend already does?"

The client is advisory; anyone can bypass it with devtools or curl. The server is authoritative — the only place a rule is actually enforced. Frontend validation is UX; backend validation is correctness and security.

"What does middleware do?"

Runs before (and optionally after) the controller, and can reject the request outright — auth, rate limiting, CSRF, tenant resolution. Add: it is why controllers can assume a valid user exists.

"Explain route model binding."

A type-hinted Eloquent parameter whose name matches the URI segment is resolved from the database automatically; no match returns 404 before the method runs. Customise the column with {post:slug}.

"Service layer — why bother?"

Keeps business logic out of controllers so it is reusable (HTTP, CLI, queue) and testable without HTTP. Honest caveat worth voicing: it is overkill for simple CRUD; it earns its place when logic is shared or complex.

"Tell me about multi-tenancy." (your differentiator)

Say what is true: you have read a production single-database implementation — one database, a tenant_id column, a global scope appending the filter automatically. Name the real hazard: the scope is a no-op outside tenant context, so a queue job or admin panel can silently read every tenant's rows. Do not claim to have built one; the follow-ups will find the edge.

The one difference that trips people

Middleware and exception handling live in app/Http/Kernel.php in Laravel 10, but in bootstrap/app.php from 11 onward. If a tutorial references a file you do not have, check the version first.
