2The access distinction

ExpressionResult
$student->mosqueRuns a query, returns the model, caches it
$student->mosque()Returns a builder — chain where(), then get()
$student->relationLoaded('mosque')True if already eager loaded
The rule

Property access inside a loop = one query per iteration. Always eager load what a loop, a Resource, or an export will touch.

3Eager loading recipes

PatternUse when
::with('mosque')You will read the relation
::with(['mosque', 'plan'])Several relations
::with('sections.teacher')Nested — dot notation
::with(['mosque' => fn($q) => $q->select('id','name')])Column pruning
::withCount('students')You only need the number → $row->students_count
$model->load('mosque')Model already fetched; load after the fact
::has('students') / ::whereHas(...)Filter parents by their children

Two queries, never a join (docs):

select * from students
select * from mosques where id in (1, 2, 3, …)
withCount beats with for counting

->students->count() loads every row into memory to count them. withCount('students') asks the database for the number. On a list endpoint the difference is large.

4Eager loading re-applies global scopes

Each eager-loaded relation is its own query against its own model, so it re-applies that model's global scopes — including TenantScope and TermScope. A correctly scoped parent does nothing for it.

Symptom: blank columns on rows that plainly have data. No error.

Fix (Ethaaf's crossTenant()):

$query->withoutGlobalScopes([StanclTenantScope::class, TermScope::class]);

Safe only because the parent query is already the authorisation boundary — relations are reached by foreign key from rows that passed the check.

Carried from Reference 03

Scopes come off by class name. Never bare withoutGlobalScopes(). And fail closed: an empty filter list must match nothing ($ids ?: ['__none__']), never everything.

6Version delta — what differs outside Laravel 10

Ethaaf is on 10.50.2. This table is for reading newer docs, blog posts and AI answers without being misled. Nothing here is something you write today.

The skeleton is opt-in, not forced

Laravel's own upgrade guide: "we do not recommend that Laravel 10 applications upgrading to Laravel 11 attempt to migrate their application structure, as Laravel 11 has been carefully tuned to also support the Laravel 10 application structure." Estimated upgrade time: 15 minutes. The structure is a new-app default, not a migration requirement.
