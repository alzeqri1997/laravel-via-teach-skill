Request Lifecycle & Project Map

The seven stages, the folders that matter, and the commands worth memorising. Built to print on two sides.

Laravel 13.x · from Lesson 1

The seven stages

① REQUEST        GET /halaqas/42
     ↓
② ENTRY          public/index.php      — single entry point, always
     ↓
③ BOOTSTRAP      bootstrap/app.php     — .env, config, providers
     ↓
④ ROUTER         routes/web.php        — which code handles this URL?
     ↓                routes/api.php        — stateless / token-auth routes
⑤ MIDDLEWARE     app/Http/Middleware/  — auth? csrf? WHICH TENANT?
     ↓
⑥ CONTROLLER     app/Http/Controllers/ — your code runs here
     ↕
   MODEL          app/Models/           — Eloquent → SQL → database
     ↓
⑦ RESPONSE       resources/views/      — Blade HTML, or JSON
     ↓
   PROCESS DIES   — nothing survives except session / cache / DB
Rule of thumb

Lost in an unfamiliar codebase? Find the route first. It names the controller, which names the model. The route file is the index to everything else.

Folder map — what lives where

PathWhat is in it
routes/web.phpBrowser routes. Sessions + CSRF. Start reading here.
routes/api.phpAPI routes. Stateless, token auth, no session.
app/Http/Controllers/Request handlers. The methods routes point at.
app/Http/Middleware/Gatekeepers. Auth, tenant resolution, rate limits.
app/Http/Requests/Form Requests — validation rules, extracted from controllers.
app/Models/Eloquent models. One class ≈ one table.
app/Policies/Authorization: may this user touch this record?
database/migrations/Executable schema history, in timestamp order.
database/seeders/Fake/initial data for local development.
database/factories/Model blueprints for tests. Invaluable later.
resources/views/Blade templates (.blade.php).
resources/js/Vue/React source, if the app uses Inertia or a bundled SPA.
config/Config arrays. Read .env; never hardcode secrets.
tests/Feature + Unit tests. Your safety net for changing code.
.envSecrets and per-machine settings. Never committed.
composer.jsonPHP dependencies. Tells you which packages the app leans on.

Artisan commands worth knowing by heart

Orientation — safe to run anywhere

php artisan --version
php artisan route:list
php artisan route:list --path=halaqa
php artisan about

Local development

php artisan serve
php artisan tinker        # REPL: poke at models live
php artisan migrate
php artisan migrate:fresh --seed

Generating files

php artisan make:model Halaqa -mfc
php artisan make:controller HalaqaController
php artisan make:migration add_x_to_y_table
php artisan make:request StoreHalaqaRequest
php artisan make:test HalaqaTest

When things behave strangely

php artisan optimize:clear
php artisan config:clear
php artisan tail          # live log stream
On -mfc

make:model Halaqa -mfc generates the model plus its migration, factory and controller in one shot. It is the single most useful flag combination in Artisan.

Never run against production

migrate:fresh and migrate:refresh drop every table. They are local-sandbox commands. Check which database .env points at before either one leaves your fingers.

Multi-tenancy — the standing hazard

One codebase, many organizations, one database. Rows carry a tenant_id, and a global scope silently appends WHERE tenant_id = ? to every query on a tenant-aware model.

Halaqa::all()                    // scoped — safe
Halaqa::withoutGlobalScopes()->get()   // UNSCOPED — every tenant. Danger.
DB::table('halaqas')->get()            // UNSCOPED — bypasses Eloquent entirely.
Two habits that prevent the worst bug in this codebase

1. Prefer Eloquent models over the DB:: query builder. The query builder knows nothing about tenants.
2. Treat withoutGlobalScopes() as a red flag in review — yours or anyone's. It is occasionally correct and usually a leak.

Confirm the actual mechanism in your codebase before trusting this page: composer show | Select-String tenan reveals whether it uses stancl/tenancy, spatie/laravel-multitenancy, or a hand-rolled scope.
